# Landing backtest report

Generated by `make backtest` (scripts/backtest_landing.py) with data as of 2026-11-16. The landing was recomputed for each of the last 24 closed months (Nov 2024 to Oct 2026), as of the 15th of that month, using only the actuals of earlier months and the forecasts already published then. All numbers below are measured on the synthetic data of this prototype.

## Goals

| Goal | Measured | Met |
|---|---|---|
| Ensemble beats the plain latest forecast on group billing WAPE | 0.99% vs 2.28% | yes |
| P10-P90 coverage between 70% and 90% (BU billing) | 73.7% | yes |

Group-level billing coverage (one total per month, 24 months): 95.8%.
This is above the 70-90% band: at group level the P10-P90 range is wider than needed. With only 24 monthly totals one month moves coverage by about 4 points; a next step is to calibrate the common shock of the simulation on group-level errors.

## Where the landing is weaker

Measured cases where the latest forecast as published beats the landing:

- Group revenue (as booked): WAPE 3.13% vs 2.31% for the latest forecast.
- Group operating profit (as booked): WAPE 19.21% vs 8.66% for the latest forecast.
- BU operating profit (as booked): WAPE 36.97% vs 36.68% for the latest forecast.
- Lumpy (project billing) BUs, billing: WAPE 19.37% vs 17.75% for the latest forecast.

Suggested next steps: for revenue and operating profit as booked, add a WIP estimate for the landing month (the WIP = 0 rule is the main error source); for lumpy BUs, lean on the latest forecast (raise its weight for the class) and keep the wide ranges.

## Accuracy by method (billing, revenue, operating profit)

WAPE = sum of absolute errors / sum of actuals. Group = one total per month; BU = every BU and month. Operating profit is shown as booked and like-for-like: the landing rule sets WIP to 0 in the landing month, so the like-for-like view removes the month's WIP movement from the actuals and from the forecast before comparing.

Revenue is compared with actual revenue, which includes WIP; the landing assumes WIP = 0 in the landing month, so part of the revenue error is the month's actual WIP movement. WIP swings are large relative to operating profit (for example the December WIP release), which is why the as-booked operating profit error is much higher than the like-for-like error.

## Method notes

- Working-day elasticity estimated from history at the latest origin: 0.68.
- Ensemble weights per BU: inverse WAPE over the previous 12 origins, shrunk toward the weights of the BU's pattern class; methods without enough history are left out.
- P10 / P90: empirical 10th / 90th percentiles of the ensemble's own past errors (per BU with at least 18 past months, otherwise per pattern class); aggregates use a seeded simulation (common shock plus BU-specific error).
- Pattern classes at the latest origin: Lumpy (project billing) 19, Quarter-end loaded 44, Seasonal (March peak, August dip) 9, Steady 23, Year-end loaded 11.

Run time: 132 s for 106 BUs.
